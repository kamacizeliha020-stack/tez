# Contributing

## Before opening a pull request

- Read `RESEARCH_INTEGRITY.md`.
- Keep empirical data, derived outputs, and synthetic fixtures separate.
- Include tests for new preprocessing, schema, model, or report behavior.
- Record configuration and version changes in the relevant manifest.
- Do not add secrets, access tokens, or identifiable student information.
- Do not state or imply that an experiment was completed unless its run artifact exists.

## Pull request size

Each pull request must remain at or below 3,000 textual words. If a phase needs more documentation, split it into multiple small pull requests and accumulate the phase threshold across them.

## Review expectations

Reviewers should check scientific validity, data leakage, privacy, reproducibility, test coverage, and whether every reported claim is supported by repository evidence.
